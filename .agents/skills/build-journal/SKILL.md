# build-journal

1. Append a dated 8–12-line work-session entry to docs/BUILD_LOG.md with objective, changes, problems, fixes/reasons, actual validation commands/results, open issues and next action.
2. Keep earlier results intact. Append corrections when new evidence changes a conclusion.
3. Update DATA_AUDIT only with measured evidence; DECISIONS only for significant choices with reason, alternative and tradeoff.
4. Explain implemented components briefly in LEARNING_NOTES: purpose, application flow, concept and interview question; link official documentation.
5. Record AI/web contributions and reviewer involvement in AI_USAGE. State human verification only when the user actually performed it.
6. Mark PLAN acceptance criteria complete only with evidence. Keep README status and screenshot consistent with the running implementation.
