# build-journal

1. Group docs/BUILD_LOG.md entries by phase and actual IST date. Use 4–7 concise bullets per phase for meaningful changes, discoveries, failures/fixes, decisions and executed validation/results. Avoid repeated template headings and command transcripts.
2. Preserve recorded facts and significant failures. Append factual corrections. Phase 1 was editorially condensed once with user authorization; its original remains in Git history. Do not repeatedly rewrite previous phases.
3. Update DATA_AUDIT only with measured evidence; DECISIONS only for significant choices with reason, alternative and tradeoff.
4. Explain implemented components briefly in LEARNING_NOTES: purpose, application flow, concept and interview question; link official documentation.
5. Record AI/web contributions and reviewer scope in AI_USAGE without duplicating build history. State human verification only when the user actually performed it. Keep detailed data evidence in DATA_AUDIT and README near one page.
6. Mark PLAN acceptance criteria complete only with evidence. Keep README status and screenshot consistent with the running implementation.
